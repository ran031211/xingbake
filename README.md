# 星巴克中国门店布局诊断

基于 **6,947 家**星巴克中国门店的公开门店清单，做一次完整的数据清洗、多维分析与决策可视化。

项目的重点不在于"门店数最多的城市是哪个"，而在于**先验证数据能不能用，再把数据翻译成可执行的调整动作**。

**[→ 在线预览看板](https://starbucks-cn-store-dashboard.app.workbuddy.host/)** ｜ [决策摘要报告](report/星巴克门店布局诊断与调整建议报告.docx)（8 页 Word）

## 一、先说数据：这份数据是"坏"的

直接对原始表做 `value_counts`，会得到 **36 个省级行政区、267 个城市**。这个结论是错的。

原因是四类字段之间存在**系统性串位**：

| 问题 | 行数 | 表现 |
|---|---|---|
| 坐标越界 | 26 | 经度/纬度超出中国境内合理范围，无法定位 |
| 省份列串位 | 8 | 省份字段里混入营业时间 `07:00:00`、纬度 `31.1991835597287` |
| 城市列串位 | 5 | 城市字段里混入 `06:00:00`、经度 `121.473255157143` |
| 营业时间字段污染 | 76 | 时间字段被坐标/时间值覆盖，无法解析，或开店时间 = 闭店时间 |

去重后共 **99 行异常（占 1.4%）**；逐项相加是 110 处，差额来自部分记录同时存在多类异常。

**清洗动作**（`src/analyze.py`）：

1. **坐标**：按中国经纬度合理区间（经度 73–136、纬度 3–54）判定，标记 `geo_ok`
2. **省市列**：用中文行政区命名正则校验（`省/市/自治区`、`市/地区/自治州/盟/区`）判定，标记 `prov_ok` / `city_ok`
3. **营业时间**：正则解析 `HH:MM`，跨零点加 24h 归一
4. **疑似全天**：开店时间 = 闭店时间的 59 家，营业时长置为缺失值而非按 0 处理

> 修正后口径：**29 个省级行政区、263 个城市、6,921 条可定位记录**。
> 其中 6 条省市字段异常，地图仅渲染省市信息完整且坐标有效的 **6,915 个点位**。

## 二、核心结论

### 1. 单城密度见顶，省域渗透不足

Top5 省份占据 **64.8%** 的门店，Top5 城市占 **39.0%**。上海市以 **1,112 家**居首，是全国唯一单城破千的城市；而广东省单城平均 **47 家**，内蒙古仅 **3.2 家**。

用「单城门店数 × 覆盖城市数」做四象限，可以区分两类完全不同的问题：**密度见顶**（该加密转为提效）与**渗透不足**（该铺开新增）。识别出 **12 个待加密增长的省级行政区，共 1,484 家门店**。

### 2. 场景结构单极，抗风险能力偏弱

按门店名称关键词归类：商场/购物中心系 **2,341 家（33.7%）**，交通枢纽类仅 **299 家**。渠道过度依赖商业地产，客流受商场经营状况直接传导。

### 3. 营业时段高度同质，早高峰供给偏窄

**52.5%** 的门店挤在 **06:31–07:00** 这半小时内开门。供给曲线是尖峰而非平台——写字楼商圈的早高峰（07:30–09:00）与社区夜间需求都缺少覆盖。

### 4. 营业时长结构性偏长，人力成本刚性

平均营业 **13.65 小时**，中位数 **14 小时**；营业 **≥14 小时的有 4,188 家，占 60.3%**。长时段营业意味着排班人力成本刚性，但其中相当一部分时段的产出（如 06:00 前、22:00 后）并未被验证。

**对应的调整动作与优先级**（完整版见[报告](report/星巴克门店布局诊断与调整建议报告.docx)）：把新开店预算的 60% 投向 12 个待加密省份；压缩低产出营业时段，把释放的人力补到早班与午市峰值；在枢纽与社区场景试点差异化店型。

## 三、看板

`dashboard/index.html` —— **单文件、零外部依赖**（ECharts 已内联），可直接双击打开或扔到任意静态托管。

- 4 张分析图：单城密度象限、场景结构、开门时段分布、营业时长分布
- 1 张全国门店地图：6,915 个点位，腾讯地图 JS API GL 点聚合，支持**按省份下钻检索**
- 优先级矩阵与行动清单

> 地图底图需要自己的腾讯位置服务 Key。申请后替换 `dashboard/index.html` 第 13 行的 `YOUR_TMAP_KEY` 即可（[申请入口](https://lbs.qq.com/dev/console/key/manage)，应用类型选「Web端(JS API)」）。
> 不配置也能打开：地图区提示"底图未加载"，其余图表与结论全部正常。

## 四、项目结构

```
.
├── data/
│   └── 星巴克门店.xlsx            # 原始数据 6,947 × 8
├── src/
│   ├── analyze.py                 # 清洗 + 多维统计，产出 outputs/
│   └── build_dashboard.py         # 生成单文件看板 HTML
├── assets/
│   └── echarts.min.js             # ECharts 5.4.3，构建时内联进 HTML
├── outputs/starbucks/
│   ├── starbucks_clean.csv        # 清洗后全量（含 geo_ok/prov_ok/city_ok 校验列）
│   ├── starbucks_points.csv       # 可定位点位 6,921 条
│   └── summary.json               # 全部结论的权威口径（看板与报告均以此为准）
├── dashboard/
│   └── index.html                 # 线上部署版看板
└── report/
    └── 星巴克门店布局诊断与调整建议报告.docx
```

## 五、快速开始

```bash
pip install -r requirements.txt

python src/analyze.py            # 清洗 + 统计分析 → outputs/starbucks/
python src/build_dashboard.py    # 生成看板 HTML（需先执行上一步）
```

两个脚本均使用基于项目根目录的相对路径，clone 后无需修改任何配置。

**依赖**：Python 3.10+ ｜ pandas ｜ numpy ｜ openpyxl ｜ ECharts 5.4.3 ｜ 腾讯地图 JS API GL
